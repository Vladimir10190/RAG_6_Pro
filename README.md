# HelpDesk Cloud — гибридный RAG

Веб-чат отвечает по Markdown-документам из `БЗ`. Для каждого вопроса приложение получает настоящий embedding через OpenAI-совместимый API, ищет по локальному индексу FAISS и независимо выполняет BM25. Результаты объединяются по Reciprocal Rank Fusion (RRF), дубли удаляются, а модели передаются только top-K фрагментов. Диагностика чата показывает оба списка и итоговый контекст, оценки и ссылки на исходные файлы.

## Запуск

Нужны Python 3.10+, доступ к API embeddings и модели чата.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Укажите в `.env` ключ `OPENAI_API_KEY`, при необходимости `OPENAI_BASE_URL`, а также модели `OPENAI_EMBEDDING_MODEL` и `OPENAI_CHAT_MODEL`. Не публикуйте ключ. Затем создайте индекс и запустите сервер:

```powershell
python -m app.index
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000. Проверка состояния: `/api/health`, документация API: `/docs`.

## Обновление базы

Откройте в чате раздел «База знаний и переиндексация». Выберите Markdown-файл в UTF-8 (до 1 МБ) и нажмите «Сохранить файл». Файл с тем же именем заменяется; остальные документы сохраняются. Затем нажмите «Обновить индекс» и дождитесь сообщения об успешном завершении. После этого новые документы используются в ответах без перезапуска сервера и изменения кода. Индексация создаёт embeddings через API и может быть платной.

Также можно изменить `.md` файлы непосредственно в папке `БЗ` и выполнить `python -m app.index` или нажать кнопку индексации в интерфейсе. До успешной переиндексации запросы блокируются, если документы не совпадают с индексом. При ошибке создания embeddings старый индекс сохраняется, но не используется с изменёнными документами; устраните ошибку и повторите индексацию. Смена модели embeddings также требует переиндексации.

При индексации создаётся отдельный файл `data/index-<идентификатор>.faiss`, а файл `data/chunks.json` переключается на него только после успешного завершения. Старые файлы индекса сохраняются и могут занимать место на диске. Интерфейс управления предназначен для локального использования без авторизации; не открывайте приложение в общую сеть без защиты доступа.

API: `GET /api/knowledge` возвращает список и состояние; `POST /api/knowledge/documents` принимает JSON с `filename` и `content`; `POST /api/knowledge/reindex` запускает индексацию и возвращает результат после её завершения.

## Поиск и ограничения

`RAG_TOP_K` ограничивает число фрагментов в контексте (по умолчанию 4), `RAG_MIN_SCORE` задаёт минимальное косинусное сходство для векторного канала (0.25 по умолчанию). BM25 ранжирует токены без морфологического анализа; RRF объединяет ранги каналов, а не их несопоставимые оценки. Поля диагностики API: `vector`, `bm25`, `context`; score в них соответственно cosine, BM25 и RRF. Источники ответа выбирает модель из переданного контекста, сервер проверяет идентификаторы. При отсутствии источников или некорректном формате возвращается отказ. Проверка идентификаторов не гарантирует истинность каждого утверждения: ответы следует сверять с документами.

`POST /api/chat` принимает `{"question":"Как восстановить пароль?"}` и возвращает `answer`, `sources`, `no_answer`, `diagnostics`. Ссылки на файлы доступны через `/api/documents/{filename}`. При сбое API или устаревшем индексе возвращается ошибка 503.

## Проверка

`python tests/evaluate_live.py` запускает 10 вопросов через реальный API и сохраняет ответы и полную диагностику в `tests/live_results.json`; вызовы могут быть платными. Проверяйте найденные фрагменты, ссылки и утверждения вручную: автоматическое наличие ссылок не доказывает их релевантности. Все сведения HelpDesk Cloud вымышлены.

## IntelliJ IDEA / PyCharm

Откройте эту папку через **File → Open**. В `.idea` сохранены конфигурации:

- `Server` — локальный сервер с автоматической перезагрузкой, http://127.0.0.1:8000.
- `Build_index` — создание индекса (вызывает API, может быть платным).
- `Local_tests` — локальные unittest без обращений к API.

Для IntelliJ IDEA нужна поддержка Python (плагин Python). Если IDE предлагает настроить SDK, выберите существующий интерпретатор `.venv\Scripts\python.exe` и задайте имя `Python 3.14 (RAG_6_Pro)`. Конфигурации запуска также содержат прямой путь к этому интерпретатору. Рабочая папка — корень проекта; приложение читает ключи из локального `.env`.
